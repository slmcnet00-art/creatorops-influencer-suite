# 캠페인 리포트 화면과 집계 기준

운영 메뉴 ‘리포트’에서 캠페인을 선택한다. 데이터 저장 형식과 기존 콘텐츠 등록·갱신 기능은 유지한다.

| 탭 | 표시 내용 |
| --- | --- |
| 종합 요약 | 기존 광고주용 요약, 제공 자료 발송 현황, 실제 반응 지표와 관측 추이 |
| 인플루언서별 | 배정·추적 인원 비교표 → 실제 비용 효율 → 등급·형식별 비교 → 통합 추이 |
| 콘텐츠별 | 전체 업로드의 원본 링크·썸네일·조회·좋아요·댓글·공유·저장·개별 관측 이력 |
| 유입·구매 | 캠페인에 연결된 UTM 발급, 관측 클릭, 구매·환불, 기록 매출·ROAS·CPA |
| 분석·다음 전략 | 확인된 조회·비용 근거, 다음 확인 작업, 전략·가이드 및 정산 화면 연결. 기존 성과 학습·재사용 승인은 상세에서 유지 |

## 비교와 비용

- 현재 캠페인 ID에 연결된 콘텐츠만 집계한다. 구독자·팔로워에 따른 기대 조회수와 견적 단가는 실제 실적으로 합산하지 않는다.
- 크리에이터 ID를 우선 연결하고, 없으면 동일 플랫폼의 유일한 핸들 일치만 허용한다. 이름 유사성으로 합산하지 않는다.
- 수집 불가/미확인 지표는 null을 유지한다. 확인된 0은 보존한다. 일부 합계에는 확인 건수와 ‘부분 합계’를 표시한다.
- 개인 비용은 지급 기록 합계 우선, 없으면 운영 기록의 actualCost 합계다. 두 원천에 같은 지급이 있어도 더하지 않는다. 캠페인 actualSpend가 기록돼 있으면 총액으로 사용하고, 없으면 확인 비용을 합산한다. 개인 연결이 없는 비용은 총액에 보존하고 임의로 배분하지 않는다.
- CPV = 개인 기록 비용 / 확인 조회수, CPM = CPV × 1,000. 해당 개인 콘텐츠의 조회수가 모두 확인돼야 계산한다.
- CPE = 비용 / (좋아요+댓글+공유+저장). CPE·참여율은 모든 반응 지표가 확인된 경우만 계산한다. 캠페인 비용이 부분 확인이면 전체 ROAS·CPA는 미확인으로 둔다.
- 등급은 기존 데이터 정의의 구독자·팔로워 기준이다. 콘텐츠 형식은 개별 기록 우선, 단일 캠페인 형식만 대체값으로 허용한다.

## 추이와 구매

- 최근 30일의 실제 metricHistory만 사용한다. 한국시간 일자별로 콘텐츠당 마지막 관측을 합산하며, 관측되지 않은 날은 채우지 않는다. 각 날짜의 관측 콘텐츠 수를 함께 표시한다. 관측 범위가 달라지면 단순 증감 비교에 주의한다.
- 클릭 기록이 없으면 ‘0명 유입’이라고 단정하지 않는다. 구매 수는 고유 구매자 수와 다르다.
- 주문 귀속 기록이 있으면 우선 사용하고 구매·환불 이벤트를 중복 합산하지 않는다. 캠페인 안에서 주문 ID+이벤트 유형으로 중복을 제거한다. 환불은 매출에서 차감한다.
- 보고서 다운로드의 비용·매출도 같은 계산을 적용하며 비용 부분 확인 시 효율 확정을 보류한다. 개별 탭 비교표의 별도 다운로드 기능은 추가하지 않는다.

## 검증

`npm test`, `npm run lint`, `npm run build`를 실행한다. 인증/API가 비활성화된 로컬 Vite 5199에서 `python scripts/test-campaign-report-ui.py`로 실제 App의 5개 탭, 키보드, 캠페인 격리, 전략·추적 화면 이동과 모바일 넘침을 확인한다. 합성 fixture는 테스트 브라우저 저장소에만 들어가며 운영 DB에 등록하지 않는다.

`TEST_REPORT_WORKSPACE`에 별도 로컬 스냅샷을 지정하면 몽클로스 원본 자료 유지 검사도 실행한다. 해당 스냅샷은 저장소에 넣지 않는다. `TEST_REPORT_SCREENSHOTS`는 선택적인 캡처 폴더다.
